# 微信小程序复习

> 微信小程序是一种不需要下载安装即可使用的应用，基于 WXML/WXSS/JS 开发，运行在微信客户端中，具有即用即走、跨平台、原生体验等特点。

## 一、小程序简介

### 1.1 什么是小程序

微信小程序是腾讯推出的一种**无需下载安装即可使用**的应用，用户扫一扫或搜一下即可打开，体现了「用完即走」的理念。

**核心特点：**

- **无需下载安装**：在微信内直接运行，不占用手机存储
- **即用即走**：用户体验轻量，适合低频场景
- **跨平台**：一套代码同时运行在 iOS、Android、PC 微信
- **原生体验**：可调用微信原生能力（支付、位置、扫码等）
- **入口丰富**：扫码、搜索、分享、公众号关联、附近的小程序

### 1.2 小程序与普通网页的区别

| 对比项 | 小程序 | 普通网页 |
| --- | --- | --- |
| 运行环境 | 微信客户端（双线程：逻辑层 + 视图层） | 浏览器（单线程） |
| 开发语言 | WXML / WXSS / JS | HTML / CSS / JS |
| DOM 操作 | 不支持 DOM/BOM，通过数据驱动视图 | 可直接操作 DOM |
| API 能力 | 可调用原生能力（支付、位置、文件等） | 受浏览器沙箱限制 |
| 包体积限制 | 主包 ≤ 2MB，分包总计 ≤ 20MB | 无强制限制 |
| 审核机制 | 需提交审核发布 | 无需审核 |
| 路由 | 由微信框架管理页面栈 | 由浏览器/前端路由管理 |

> ⚠️ 小程序没有浏览器的 DOM 和 BOM 对象，`document`、`window`、`localStorage` 均不可用，需使用 `wx.setStorageSync` 等 API 替代

### 1.3 注册与开发准备

**开发准备三步走：**

1. **注册小程序账号**：在 [mp.weixin.qq.com](https://mp.weixin.qq.com/) 注册，获取 `AppID`
2. **下载微信开发者工具**：官方 IDE，支持代码编辑、调试、预览、上传
3. **创建项目**：填入 AppID，选择不使用云服务，生成初始目录结构

**初始目录结构：**

```
├── pages/              页面目录
│   └── index/
│       ├── index.js    页面逻辑
│       ├── index.json  页面配置
│       ├── index.wxml  页面结构
│       └── index.wxss  页面样式
├── utils/              工具函数目录
├── app.js              小程序入口逻辑
├── app.json            全局配置
├── app.wxss            全局样式
├── project.config.json  项目配置（AppID、编译设置）
└── sitemap.json        搜索索引配置
```

> 💡 AppID 是小程序的唯一标识，开发阶段可使用「测试号」，但发布必须使用正式 AppID

## 二、目录结构与配置

### 2.1 全局文件

| 文件 | 作用 | 说明 |
| --- | --- | --- |
| `app.js` | 小程序入口逻辑 | 通过 `App()` 注册，定义全局数据和生命周期 |
| `app.json` | 全局配置 | 配置页面路径、窗口、tabBar 等 |
| `app.wxss` | 全局样式 | 所有页面共享的样式 |
| `project.config.json` | 项目配置 | 工具相关：AppID、编译模式、ES6 转 ES5 等 |
| `sitemap.json` | 搜索索引配置 | 控制小程序页面是否允许被微信搜索索引 |

**app.js 示例：**

```js
App({
  // 全局数据
  globalData: {
    userInfo: null,
    token: ''
  },
  // 小程序启动时触发（全局只触发一次）
  onLaunch() {
    console.log('小程序启动')
  },
  onShow() {
    console.log('小程序显示')
  },
  onHide() {
    console.log('小程序进入后台')
  }
})
```

### 2.2 页面文件

每个页面由 4 个同名文件组成：

| 文件 | 作用 |
| --- | --- |
| `.js` | 页面逻辑，通过 `Page()` 注册 |
| `.wxml` | 页面结构（类似 HTML） |
| `.wxss` | 页面样式（类似 CSS） |
| `.json` | 页面配置（导航栏标题、是否允许下拉刷新等） |

**页面 .json 示例：**

```json
{
  "usingComponents": {},
  "navigationBarTitleText": "首页",
  "enablePullDownRefresh": true,
  "backgroundColor": "#f5f5f5"
}
```

**配置项说明：**

| 配置 | 作用 |
| --- | --- |

| `tabBar` | 底部导航栏，**至少 2 个、最多 5 个 tab** |
| `style` | `v2` 启用新版组件样式 |
| `networkTimeout` | 网络请求超时时间 |

> ⚠️ tabBar 中 `pagePath` 对应的页面必须出现在 `pages` 列表中；图标大小限制 40KB，建议尺寸 81×81

## 三、WXML 模板语法

### 3.1 数据绑定 {{ }}

使用 Mustache 语法将 JS 数据渲染到视图：

```html
<!-- pages/home/home.wxml -->
<view>{{ message }}</view>
<view>姓名：{{ user.name }}，年龄：{{ user.age }}</view>
<view>价格：{{ price }} 元</view>
<view>{{ price > 100 ? '贵' : '便宜' }}</view>
<view>{{ [1, 2, 3].length }}</view>
```

```js
// pages/home/home.js
Page({
  data: {
    message: 'Hello 小程序',
    user: { name: '张三', age: 18 },
    price: 199
  }
})
```

> ⚠️ `{{}}` 中不能调用方法，只能写简单表达式；不能使用 `if`、`for` 等语句

### 3.2 列表渲染 wx:for / wx:key

```html
<!-- 基础列表 -->
<view wx:for="{{ list }}" wx:key="index">
  索引：{{ index }}，值：{{ item }}
</view>

<!-- 对象数组列表 -->
<view wx:for="{{ goodsList }}" wx:key="id">
  {{ item.name }} - ¥{{ item.price }}
</view>

<!-- 重命名 index 和 item -->
<view wx:for="{{ arr }}" wx:for-item="num" wx:for-index="i" wx:key="*this">
  第 {{ i }} 个：{{ num }}
</view>
```

```js
Page({
  data: {
    list: ['苹果', '香蕉', '橘子'],
    goodsList: [
      { id: 1, name: '手机', price: 2999 },
      { id: 2, name: '电脑', price: 5999 }
    ],
    arr: [10, 20, 30]
  }
})
```

**wx:key 取值说明：**

| wx:key 值 | 说明 |
| --- | --- |
| `id`（字段名） | 使用列表项的唯一字段，**推荐** |
| `*this` | 列表项本身是字符串/数字且唯一时使用 |
| `index` | 使用索引（不推荐，列表变动会有性能问题） |

> ⚠️ 不写 `wx:key` 会报警告，且列表重新渲染时会重新创建所有节点，影响性能和组件状态保留

### 3.3 条件渲染 wx:if / hidden

```html
<!-- wx:if 系列 -->
<view wx:if="{{ score >= 90 }}">优秀</view>
<view wx:elif="{{ score >= 60 }}">及格</view>
<view wx:else="">不及格</view>

<!-- hidden -->
<view hidden="{{ !isLogin }}">请先登录</view>
```

**wx:if 与 hidden 对比：**

| 对比项 | wx:if | hidden |
| --- | --- | --- |
| 实现方式 | 动态创建/移除节点 | 通过 `display: none` 控制显隐 |
| 初始渲染 | `false` 时不渲染，节省首次开销 | 始终渲染，初始开销大 |
| 切换开销 | 切换时重新创建销毁，开销大 | 仅切换 CSS，开销小 |
| 使用场景 | 不频繁切换、初始可能不显示 | 频繁切换显隐 |

> 💡 选择原则：**频繁切换用 `hidden`，条件少变用 `wx:if`**

### 3.4 事件绑定

| 写法 | 说明 |
| --- | --- |
| `bind:tap` / `bindtap` | 绑定事件（允许冒泡） |
| `catch:tap` / `catchtap` | 绑定事件并**阻止冒泡** |
| `mut-bind:tap` | 互斥事件绑定 |
| `capture-bind:tap` | 捕获阶段绑定 |

```html
<view bindtap="handleTap" data-id="{{ item.id }}" data-name="{{ item.name }}">
  点击我
</view>

<button bindtap="handleAdd" type="primary">+1</button>

<input bindinput="handleInput" placeholder="请输入" />

<!-- 阻止冒泡 -->
<view bindtap="parentTap">
  <view catchtap="childTap">子元素（点击不会触发 parentTap）</view>
</view>
```

```js
Page({
  handleTap(e) {
    // e.currentTarget.dataset 获取自定义数据
    console.log(e.currentTarget.dataset.id)
    console.log(e.currentTarget.dataset.name)
  },
  handleAdd(e) {
    console.log(e)  // 完整事件对象
  },
  handleInput(e) {
    // 输入框值通过 e.detail.value 获取
    console.log(e.detail.value)
  }
})
```

**事件对象 e 关键属性：**

| 属性 | 说明 |
| --- | --- |
| `e.type` | 事件类型 |
| `e.target` | 触发事件的源组件（可能被子元素触发） |
| `e.currentTarget` | 事件绑定的当前组件（推荐用此取 dataset） |
| `e.detail` | 额外信息（如 input 的 value、scroll 的 scrollTop） |
| `e.currentTarget.dataset` | 自定义属性 `data-*` 的集合 |

> ⚠️ `e.target` 是真正点击的元素，`e.currentTarget` 是绑定事件的元素，取自定义数据**推荐用 `e.currentTarget.dataset`**

### 3.5 模板 template

```html
<!-- 定义模板 -->
<template name="goodsCard">
  <view class="card">
    <image src="{{ item.img }}" mode="aspectFill" />
    <view>{{ item.name }}</view>
    <view>¥{{ item.price }}</view>
  </view>
</template>

<!-- 使用模板并传参 -->
<template is="goodsCard" data="{{ item: goods }}" />
```

> 💡 模板拥有自己的作用域，只能通过 `data` 传入数据；不能直接使用页面 data 中的其他变量

## 四、WXSS 样式

### 4.1 尺寸单位 rpx

`rpx`（responsive pixel）是小程序的响应式像素单位，**会根据屏幕宽度自适应**：

- 规定屏幕宽度统一为 `750rpx`（无论设备物理尺寸）
- 以 iPhone6（物理宽度 375px）为基准：`1rpx = 0.5px`，即 `1px = 2rpx`

| 设备 | 屏幕宽度 | 1rpx = ? px |
| --- | --- | --- |
| iPhone5 | 320px | 0.42px |
| iPhone6 | 375px | 0.5px |
| iPhone6 Plus | 414px | 0.552px |

> ⚠️ 设计稿通常是 iPhone6 尺寸（750px 宽），量出来的 px 值直接写成 rpx 即可；不要在小程序里写 `rem`、`vw`，用 `rpx` 最方便

### 4.2 样式导入 @import

```css
/* common.wxss */
.btn {
  padding: 20rpx;
  border-radius: 8rpx;
}
```

```css
/* page.wxss 导入公共样式 */
@import "../../common.wxss";

.container {
  display: flex;
}
```

### 4.3 内联样式

```html
<view style="color: {{ color }}; font-size: {{ size }}rpx;">动态样式</view>
```

> ⚠️ 频繁切换的样式建议用 `class`，内联 `style` 动态绑定会有一定性能开销

### 4.4 选择器

| 选择器 | 示例 | 说明 |
| --- | --- | --- |
| 类选择器 | `.box` | 最常用 |
| id 选择器 | `#header` | - |
| 元素选择器 | `view` | - |
| 伪元素 | `view::before` / `view::after` | 必须设置 `content` |
| 并集/后代 | `.a, .b` / `.parent .child` | - |

> ⚠️ 小程序**不支持**通配符 `*`、属性选择器 `[type=text]`、伪类 `:hover`（用 `hover-class` 替代）

### 4.5 全局样式与局部样式

- **全局样式**：定义在 `app.wxss`，作用于所有页面
- **局部样式**：定义在页面 `.wxss`，只作用于当前页面

> ⚠️ 当全局样式与局部样式冲突时，**局部样式优先级更高**（同级选择器下）；权重相同时局部覆盖全局

## 五、JS 逻辑与生命周期

### 5.1 App() 全局逻辑

```js
App({
  globalData: {
    userInfo: null,
    token: '',
    baseUrl: 'https://applet-base-api-t.itheima.net'
  },
  onLaunch() {
    // 小程序初始化完成，全局只触发一次
    console.log('onLaunch')
  },
  onShow() {
    // 小程序从后台进入前台
    console.log('onShow')
  },
  onHide() {
    // 小程序从前台进入后台
    console.log('onHide')
  }
})
```

**在其他页面获取 App 实例：**

```js
const app = getApp()
console.log(app.globalData.token)
```

### 5.2 Page() 页面逻辑

```js
Page({
  data: {
    count: 0,
    list: []
  },

  // 页面加载（只触发一次，可获取路由参数）
  onLoad(options) {
    console.log('onLoad', options)
  },

  // 页面显示（每次显示都触发）
  onShow() {
    console.log('onShow')
  },

  // 页面初次渲染完成
  onReady() {
    console.log('onReady')
  },

  // 页面隐藏
  onHide() {
    console.log('onHide')
  },

  // 页面卸载（navigateBack / redirectTo 时触发）
  onUnload() {
    console.log('onUnload')
  },

  // 下拉刷新
  onPullDownRefresh() {
    console.log('下拉刷新')
    this.loadData()
  },

  // 上拉触底
  onReachBottom() {
    console.log('上拉触底，加载更多')
    this.loadMore()
  },

  // 分享
  onShareAppMessage() {
    return {
      title: '快来看看这个好物',
      path: '/pages/detail/detail?id=123'
    }
  },

  // 自定义方法
  handleAdd() {
    this.setData({ count: this.data.count + 1 })
  },

  loadData() {
    // ...
    wx.stopPullDownRefresh()
  },

  loadMore() {
    // ...
  }
})
```

**App / Page / Component 生命周期对比：**

| 类型 | 生命周期函数 |
| --- | --- |
| App | `onLaunch` → `onShow` → `onHide` |
| Page | `onLoad` → `onShow` → `onReady` → `onHide` → `onUnload`；额外：`onPullDownRefresh`、`onReachBottom`、`onShareAppMessage`、`onPageScroll` |
| Component | `created` → `attached` → `ready` → `moved` → `detached` |

> 💡 `onLoad` 只触发一次且能拿到路由参数，`onShow` 每次显示都触发；从详情页返回列表页时，列表页的 `onShow` 会触发但 `onLoad` 不会

### 5.3 setData 注意事项

```js
// ✅ 正确：直接修改 data 中对象的某个属性
this.setData({
  'user.name': '李四',
  count: this.data.count + 1
})

// ❌ 错误：直接修改 this.data 不会更新视图
this.data.count++
```

**setData 的原理与注意点：**

- `setData` 会将数据从逻辑层（JS）发送到视图层（WXML），**通信是异步的**
- 小程序采用双线程模型，频繁/大量 `setData` 会造成通信开销和渲染卡顿

| 注意点 | 说明 |
| --- | --- |
| 不要设置不在 WXML 中使用的数据 | 不显示的数据应直接挂在 `this` 上，不进 `data` |
| 避免一次性 set 大量数据 | 单次数据量过大影响渲染性能，建议分批 |
| 避免频繁 setData | 如滚动场景频繁 set 会卡顿，可节流 |
| 不要把回调相关数据塞 data | 与视图无关的逻辑变量应放 `this` 上 |

> ⚠️ `this.data.count++` 这种直接改 `data` 的写法**不会触发视图更新**，必须用 `setData`

### 5.4 Component() 组件逻辑

```js
Component({
  // 组件属性（父组件传入）
  properties: {
    title: {
      type: String,
      value: '默认标题'
    },
    count: {
      type: Number,
      value: 0
    }
  },

  // 组件内部数据
  data: {
    innerVal: 1
  },

  // 组件方法
  methods: {
    handleClick() {
      // 子组件向父组件传值
      this.triggerEvent('change', { value: this.data.innerVal })
    }
  },

  // 组件生命周期
  lifetimes: {
    created() {
      // 组件实例进入页面节点树前（不能调用 setData）
      console.log('created')
    },
    attached() {
      // 组件进入页面节点树（可 setData）
      console.log('attached')
    },
    ready() {
      // 组件布局完成
      console.log('ready')
    },
    detached() {
      // 组件离开页面节点树
      console.log('detached')
    }
  }
})
```

> 💡 `created` 阶段还不能调用 `setData`，需要 setData 应放在 `attached` 中

## 六、基础组件

### 6.1 视图容器

| 组件 | 作用 | 关键属性 |
| --- | --- | --- |
| `view` | 类似 div，基础容器 | `hover-class` 长按样式 |
| `scroll-view` | 可滚动视图区域 | `scroll-y`、`scroll-x`、`bindscroll`、`refresher-enabled` |
| `swiper` | 轮播图容器 | `autoplay`、`interval`、`circular`、`indicator-dots` |
| `swiper-item` | 轮播项 | 仅可置于 `swiper` 中 |

```html
<!-- 轮播图 -->
<swiper autoplay interval="3000" circular indicator-dots indicator-active-color="#fff">
  <swiper-item wx:for="{{ banners }}" wx:key="id">
    <image src="{{ item.image_src }}" mode="aspectFill" />
  </swiper-item>
</swiper>

<!-- 可滚动区域 -->
<scroll-view scroll-y style="height: 600rpx;" bindscrolltolower="onReachBottom">
  <view wx:for="{{ list }}" wx:key="id">{{ item.text }}</view>
</scroll-view>
```

### 6.2 基础内容

| 组件 | 作用 | 关键属性 |
| --- | --- | --- |
| `text` | 文本（只能包含文本） | `selectable` 长按复制、`space` 空格处理 |
| `image` | 图片 | `src`、`mode`（缩放/裁剪模式）、`lazy-load` 懒加载 |
| `icon` | 图标 | `type`、`size`、`color` |
| `rich-text` | 富文本 | `nodes` 渲染 HTML 字符串 |

**image 的 mode 模式：**

| mode | 说明 |
| --- | --- |
| `scaleToFill` | 拉伸填满（默认，会变形） |
| `aspectFit` | 等比缩放，完整显示（图片可能留白） |
| `aspectFill` | 等比缩放，填满容器（可能裁剪） |
| `widthFix` | 宽度不变，高度自适应（常用） |
| `top` / `bottom` / `center` | 裁剪模式，不缩放 |

> ⚠️ `image` 默认宽高为 320×240，不设置宽高会按默认尺寸显示；列表图建议用 `lazy-load` 优化性能

### 6.3 表单组件

### 7.2 Promise 封装 wx.request

```js
// utils/request.js
const BASE_URL = 'https://applet-base-api-t.itheima.net'

const request = (options) => {
  return new Promise((resolve, reject) => {
    wx.request({
      url: BASE_URL + options.url,
      method: options.method || 'GET',
      data: options.data || {},
      header: options.header || {},
      success(res) {
        if (res.data.meta && res.data.meta.status === 200) {
          resolve(res.data)
        } else {
          wx.showToast({ title: res.data.meta.msg || '请求失败', icon: 'none' })
          reject(res.data)
        }
      },
      fail(err) {
        wx.showToast({ title: '网络异常', icon: 'none' })
        reject(err)
      }
    })
  })
}

export default request
```

### 8.6 下拉刷新与上拉加载

**配置（app.json 或页面 .json）：**

```json
{
  "enablePullDownRefresh": true,
  "backgroundColor": "#f5f5f5",
  "onReachBottomDistance": 50
}
```

**页面逻辑：**

```js
Page({
  data: {
    list: [],
    page: 1,
    total: 0,
    isLoading: false
  },

  // 下拉刷新：重置数据
  onPullDownRefresh() {
    this.setData({ page: 1, list: [] })
    this.loadList().then(() => {
      wx.stopPullDownRefresh()  // 必须手动停止
    })
  },

  // 上拉加载：追加数据
  onReachBottom() {
    if (this.data.isLoading) return
    if (this.data.list.length >= this.data.total) {
      wx.showToast({ title: '没有更多了', icon: 'none' })
      return
    }
    this.setData({ page: this.data.page + 1 })
    this.loadList()
  },

  async loadList() {
    this.setData({ isLoading: true })
    const res = await request({
      url: '/api/public/v1/goods/search',
      data: { pagenum: this.data.page, pagesize: 10 }
    })
    const newList = this.data.list.concat(res.message.goods)
    this.setData({ list: newList, total: res.message.total, isLoading: false })
  }
})
```

> ⚠️ 下拉刷新动画需手动调用 `wx.stopPullDownRefresh()` 停止；上拉加载需做**防重复加载**和**加载完毕判断**

## 十、分包加载

### 10.1 什么是分包

将小程序拆分为**主包 + 子包**，主包包含首页等核心页面，子包按需下载，优化首次启动速度。

- 主包：放置默认启动页和 tabBar 页面
- 子包：放置非首屏的模块化页面
- 用户进入子包页面时，微信自动下载对应子包

| 限制项 | 大小 |
| --- | --- |
| 单个分包 / 主包 | ≤ 2MB |
| 整个小程序所有包 | ≤ 20MB |

### 10.2 配置分包

```json
{
  "pages": [
    "pages/home/home",
    "pages/list/list"
  ],
  "subpackages": [
    {
      "root": "packageA",
      "name": "pkgA",
      "pages": [
        "pages/detail/detail",
        "pages/order/order"
      ]
    },
    {
      "root": "packageB",
      "pages": [
        "pages/pay/pay"
      ]
    }
  ]
}
```

对应目录结构：

```
├── pages/                主包页面
├── packageA/             分包 A
│   └── pages/
│       ├── detail/
│       └── order/
└── packageB/             分包 B
    └── pages/
        └── pay/
```

> ⚠️ tabBar 页面必须放在主包；子包不能嵌套子包；分包间可互相引用资源

### 10.3 分包预下载

```json
{
  "preloadRule": {
    "pages/home/home": {
      "network": "all",
      "packages": ["packageA", "packageB"]
    },
    "pages/list/list": {
      "network": "wifi",
      "packages": ["pkgA"]
    }
  }
}
```

| 配置 | 说明 |
| --- | --- |
| `network` | 预下载网络：`all` / `wifi` |
| `packages` | 预下载的分包名或 root |

### 11.3 网络请求统一封装

项目中所有接口走统一封装（见 7.2），统一处理：

- `baseUrl` 拼接
- 请求头 `token` 注入（从 Storage 读取）
- 响应数据状态码统一判断
- 错误统一 `wx.showToast` 提示
- 全局 loading 控制

```js
// utils/request.js（增强版）
const BASE_URL = 'https://applet-base-api-t.itheima.net'

const request = (options) => {
  // 自动注入 token
  const token = wx.getStorageSync('token')
  if (token) {
    options.header = {
      ...options.header,
      Authorization: token
    }
  }
  return new Promise((resolve, reject) => {
    wx.request({
      url: BASE_URL + options.url,
      method: options.method || 'GET',
      data: options.data || {},
      header: options.header || {},
      success(res) {
        if (res.statusCode === 200) {
          resolve(res.data)
        } else if (res.statusCode === 401) {
          // token 失效，跳登录页
          wx.removeStorageSync('token')
          wx.navigateTo({ url: '/pages/login/login' })
          reject(res)
        } else {
          wx.showToast({ title: '请求错误', icon: 'none' })
          reject(res)
        }
      },
      fail(err) {
        wx.showToast({ title: '网络异常', icon: 'none' })
        reject(err)
      }
    })
  })
}

export default request
```

### 11.4 全局数据共享

| 方式 | 适用场景 | 特点 |
| --- | --- | --- |
| `globalData` | 简单全局数据（token、用户信息） | 直接读写，无响应式 |
| `Storage` | 需持久化的数据（购物车、token） | 同步/异步 API，跨页面共享 |
| 事件总线 | 跨页面通信（如登录后刷新列表） | 自行实现 `EventBus` |
| 状态管理库 | 复杂状态（MobX、Redux） | 响应式、可追溯 |

**简易事件总线：**

```js
// utils/eventBus.js
const listeners = {}
export default {
  on(event, cb) {
    (listeners[event] = listeners[event] || []).push(cb)
  },
  emit(event, data) {
    (listeners[event] || []).forEach(cb => cb(data))
  },
  off(event, cb) {
    listeners[event] = (listeners[event] || []).filter(fn => fn !== cb)
  }
}
```

### 11.5 小程序登录流程

小程序登录采用 **code 换 token** 机制，流程如下：

```
1. 前端调用 wx.login() 获取临时登录凭证 code
2. 前端将 code 发送给自己的后端服务器
3. 后端用 code + AppID + AppSecret 调用微信接口
   https://api.weixin.qq.com/sns/jscode2session
   获取 openid 和 session_key
4. 后端根据 openid 生成自定义登录态 token，返回给前端
5. 前端将 token 存入 Storage，后续请求带上
```

```js
// pages/login/login.js
Page({
  async handleLogin() {
    // 1. 获取 code
    const { code } = await wx.login()

    // 2. 发送 code 给后端
    const res = await request({
      url: '/api/public/v1/users/wxlogin',
      method: 'POST',
      data: { code }
    })

    // 3. 存储 token
    const token = res.message.token
    wx.setStorageSync('token', token)

    // 4. 跳回上一页
    wx.navigateBack()
  },

  // 获取用户信息（需用户主动点击按钮）
  handleGetUserProfile() {
    wx.getUserProfile({
      desc: '用于完善用户资料',
      success(res) {
        console.log(res.userInfo)  // 昵称、头像等
      }
    })
  }
})
```

> ⚠️ `AppSecret` 必须保存在服务端，**绝不能**下发到小程序前端；`code` 有效期仅 5 分钟，且只能使用一次

> 💡 `wx.getUserProfile` 需用户主动点击按钮触发（不能在 onLoad 自动调用）；`wx.getUserInfo` 已废弃

## 💡 关联面试题

**Q1：小程序与普通网页有什么区别？**
- 运行环境不同：小程序在微信客户端双线程运行（逻辑层 JS Core + 视图层 WebView），网页在浏览器单线程运行
- 开发语言不同：小程序用 WXML/WXSS，网页用 HTML/CSS
- 小程序不支持 DOM/BOM，通过数据驱动视图更新
- 小程序可调用原生能力（支付、位置、扫码），网页受浏览器沙箱限制
- 小程序有包体积限制（主包 2MB），需审核发布；网页无此限制

**Q2：小程序的生命周期有哪些？**
- App：`onLaunch`（初始化）→ `onShow`（前台）→ `onHide`（后台）
- Page：`onLoad`（加载，获取参数）→ `onShow`（显示）→ `onReady`（初次渲染完成）→ `onHide`（隐藏）→ `onUnload`（卸载）；还有 `onPullDownRefresh`、`onReachBottom`、`onShareAppMessage`、`onPageScroll`
- Component：`created` → `attached` → `ready` → `moved` → `detached`

**Q3：setData 的原理和注意事项？**
- 原理：小程序双线程模型，`setData` 将数据从逻辑层发送到视图层，由视图层重新渲染
- 注意：① 必须用 `setData` 才能更新视图，直接改 `this.data` 无效 ② 不要 set 不在 WXML 中使用的数据 ③ 避免一次 set 大量数据 ④ 避免频繁 setData（如滚动场景需节流）⑤ 数据路径更新可用 `'a.b.c'` 形式

**Q4：wx:if 和 hidden 的区别？**
- `wx:if`：动态创建/移除节点，`false` 时不渲染，切换开销大，适合不频繁切换
- `hidden`：始终渲染，通过 `display: none` 控制显隐，切换开销小，适合频繁切换
- 选择原则：频繁切换用 `hidden`，条件少变用 `wx:if`

**Q5：小程序页面跳转的方式有哪些？区别是什么？**
- `wx.navigateTo`：保留当前页跳转，可返回，不能跳 tabBar 页
- `wx.redirectTo`：关闭当前页跳转，不可返回，不能跳 tabBar 页
- `wx.switchTab`：跳转到 tabBar 页，关闭其他非 tabBar 页，不能带参数
- `wx.navigateBack`：返回上一页，可指定返回层数 `delta`
- `wx.reLaunch`：关闭所有页面重新打开，可跳 tabBar 页

**Q6：小程序的登录流程？**
1. 前端 `wx.login` 获取临时 `code`
2. 前端将 `code` 发给自己的后端
3. 后端用 `code` + `AppID` + `AppSecret` 调微信接口换取 `openid` 和 `session_key`
4. 后端根据 `openid` 生成自定义 `token` 返回前端
5. 前端存 `token` 到 Storage，后续请求带上
- 关键点：`AppSecret` 必须保存在服务端，`code` 有效期 5 分钟且只能用一次

**Q7：如何优化小程序的首屏加载速度？**
- **分包加载**：将非首屏页面拆分为子包，主包只放核心页面
- **分包预下载**：在关键页面预下载即将进入的分包
- **减少 setData 数据量**：只 set 视图需要的数据，不 set 无关数据
- **图片优化**：使用 `lazy-load` 懒加载、合理设置 `mode`、用 WebP 格式、CDN 压缩
- **按需引入组件**：避免引入未使用的组件
- **减少默认 data**：初始 data 不放过多数据
- **接口合并**：减少首屏请求数量，必要时服务端聚合

**Q8：rpx 是什么？如何换算？**
- `rpx` 是小程序的响应式像素单位，会根据屏幕宽度自适应
- 规定屏幕宽度恒为 `750rpx`，无论设备物理尺寸
- 以 iPhone6（宽 375px）为基准：`1rpx = 0.5px`，即 `1px = 2rpx`
- 换算公式：`rpx = (设计稿px值 / 设计稿宽度) × 750`；若设计稿为 750px 宽，量出的 px 直接当 rpx 用即可
